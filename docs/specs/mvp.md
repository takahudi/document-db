# 文書リポジトリのMVP仕様

状態は実装済み。2026-10-06にユーザーが範囲と詳細を確認し、同日にローカルMVPを実装した。型チェック、lint、7件のテスト、実ブラウザ・HTTP・stdio MCP・ファイルSQLiteによる成功条件の検証が通った。

## 背景

人間が見た目のまま編集でき、外部AIにも効率よく読ませられる説明資料の置き場を作る。
背景となる[共有会話](https://chatgpt.com/share/6ac48f0d-98a4-83ec-82a7-e6ee9181e1b3)。

## 確定事項

2026-10-06のユーザー回答に基づく。

- 最初に扱う説明資料は、この文書ツール自身の使い方を説明する資料。
- 文書は決まった部品で構成する。見出し、本文、箇条書き、表、コード、画像などを想定する。
- 任意のHTMLや独自レイアウトの取り込みは、最初のMVPでは必要としない。
- AIは、普段使うCodexなどの外部AIから接続する。
- アプリ内のAIへの修正依頼画面は、最初のMVPでは必要としない。
- 最初の利用者は自分一人で、自分のPC上で使う。
- 他の人との共有・編集は、最初のMVPには含めない。
- AIによる修正は保存前の承認画面を設けず、直接保存する。
- 必要に応じて、文書を直前の保存状態へ戻せるようにする。
- 外部AIとの接続はMCPに絞る。
- MCPで文書の一覧・取得・作成・更新を公開する。
- 部品は見出し、本文、箇条書き、表、コード、リンク、画像を対象にする。
- 太字などの基本的な装飾に対応する。
- 画像はスクリーンショットなどを手動で追加できるようにする。
- 文書の見た目は共通スタイルで整える。
- 自由な配置、列レイアウト、独自の図は、最初のMVPには含めない。
- AIに渡す画像情報は説明文と参照のみとし、画像そのものの取得は最初のMVPには含めない。
- AIによる文章修正の際も、文書内の画像を保持できるようにする。
- AIが読み書きする形式は、本文の構造だけを表すHTMLに絞る。
- 本文HTMLにはCSS、編集画面の情報、画像データそのものを含めない。
- Markdownなど別形式の入出力は、最初のMVPには含めない。

## MVPの成功条件

このツール自身の使い方を説明する文書1件で、次の一連の操作が成立すること。

1. 外部AIがMCPで文書を作成する。
2. 人間がブラウザで文書を閲覧し、見た目のまま本文や表を修正して保存する。
3. 人間がスクリーンショットを追加し、説明文を付けて保存する。
4. 外部AIが最新の本文HTMLを取得し、人間が修正した内容と画像の説明文・参照を読み取る。
5. 外部AIが文章を修正し、表や画像を保持した状態で直接保存する。
6. 人間が画面を更新してAIの修正を確認し、直前の保存状態へ戻せる。
7. アプリを終了して再起動しても、文書と画像が保持される。

このシナリオは自分一人のPC上で行う。AIの修正は直接保存し、必要なら直前の保存状態へ戻す。

## 画面と保存

- 文書一覧と、文書の閲覧・編集画面を用意する。
- 一覧にはタイトルを表示し、文書を開く操作と新規作成を用意する。フォルダーや全文検索は設けない。
- 人間も文書を新規作成し、タイトルと本文を編集できる。
- 保存ボタンで確定する。未保存の変更があることと、保存に成功したかを画面に表示する。自動保存は設けない。
- 文書には一意のIDと、保存するたびに進む版番号を持たせる。
- 文書を開いた後にAIが更新した場合、古い版をそのまま上書きせず、最新の文書を読み直す必要があると表示する。保存失敗時に編集中の内容を消さない。自動マージはしない。
- AIの変更は画面更新で確認する。リアルタイム同期は設けない。
- 直前の保存状態を1件保持し、タイトルと本文をまとめて戻せる。取り消し後は新しい版番号を発行し、その保存に対する取り消しは一度だけとする。新規作成直後は取り消し対象を持たない。
- 取り消しの対象は、人間またはAIによる文書の保存。編集中の文字入力のUndoとは別の操作とする。
- 取り消しにも現在の版番号の一致を求め、画面を開いた後の新しい保存を意図せず取り消さないようにする。
- 変更履歴の一覧、任意の過去版への復元、削除操作は最初のMVPに含めない。
- 画像はローカルに追加・保存する。PNG、JPEG、WebPを対象にし、本文には画像への参照と説明文を持たせる。本文から外れた画像ファイルの自動削除はしない。

## 部品

| 部品 | 最初に扱う範囲 |
| --- | --- |
| 見出し | 3段階の見出し |
| 本文 | 段落、太字、斜体、改行 |
| 箇条書き | 番号付き・番号なし |
| 表 | 行・列の追加と削除、見出しセル、セル内の文章。セル結合は含めない |
| コード | 改行や空白を保つコードブロック。構文強調は含めない |
| リンク | HTTPまたはHTTPSへのリンク |
| 画像 | 共通の幅に収まる表示、説明文の編集。自由な配置や切り抜きは含めない |

## AIの入出力

MCPは自分のPC上で動くstdio接続を使う。最初に接続するクライアントは、stdio対応の外部AIツールとする。

| 操作 | 入力 | 出力 |
| --- | --- | --- |
| `list_documents` | なし | 文書のIDとタイトル。本文は返さない |
| `get_document` | 文書ID | ID、タイトル、版番号、本文HTML |
| `create_document` | タイトル、本文HTML | 作成した文書のIDと版番号 |
| `update_document` | 文書ID、取得時の版番号、更新後のタイトルと本文HTML | 保存後の版番号 |

- 更新は文書全体の置き換えとする。部分更新は設けない。
- `get_document`で取得した版番号を更新時に必須とする。現在の版と異なれば保存せず、読み直しを求めるエラーを返す。
- 本文HTMLの画像参照はアプリが発行した参照を使い、文章の修正時には保持する。既存の画像参照を取り除いた場合は、画像を文書から外す編集として扱う。
- 未対応の要素・属性、不正な画像参照、実行可能な内容は、保存前にエラーにする。未対応の内容を黙って捨てて保存しない。
- HTMLのコードブロックでは、コードを実行せず文字として保持する。
- 画像そのものの取得、画像アップロード、取り消しをMCP操作として公開する機能は、最初のMVPには含めない。

## 文書の正本とトークン効率

- 保存する正本は部品で構成された構造化文書とする。人間向け表示と本文HTMLは、同じ正本から生成する。
- 人間向けとAI向けの本文を別々の正本として保存しない。
- この判断の理由は[ADR-0001](../adr/0001-single-document-source.md)に記録する。
- 人間が保存した内容を外部AIが取得でき、AIが保存した内容を人間が再編集できることを必須とする。
- 本文HTMLには見出し・段落・リスト・表・コード・リンク・画像の説明文と参照を含める。
- CSS、スクリプト、編集用の属性、ツールバー、ナビゲーション、画像データの埋め込みは含めない。
- トークン効率は、不要な画面情報を渡していないことと、本文の意味と構造が保持されることで評価する。Markdownより常に短いことや、削減率の固定値は要件にしない。
- 説明資料のサンプルで、表示画面のHTMLとMCP取得結果を同じトークナイザーで計測し、結果を残す。内容の欠落による削減は認めない。

## 技術構成

- Windowsの現在のPCで動くローカルWebアプリ。
- Node.js 24、TypeScript、ReactとVite、Node上のHTTPサーバーを使う。
- 編集はTiptap v3の部品を使い、正本はその構造化JSONとする。人間向け表示と本文HTMLの入出力で同じ部品定義を使用する。
- Tiptapの画像部品とは別に、画像の選択・アップロード・ローカル保存をアプリ側に実装する。
- SQLiteに文書、版番号、直前の保存状態を保存し、画像はローカルのデータディレクトリに保存する。
- HTTPサーバーとMCPサーバーは同じ文書操作と保存処理を使う。本文更新、直前版の保存、版番号の更新は一つのトランザクションで行う。
- Node内蔵の`node:sqlite`を使用する。確認済みのv24.16.0ではRelease candidateのAPIであり、メモリDBへの問い合わせが動作した。実装時にファイル保存とHTTP・MCP両方からの更新を検証する。
- HTTPはループバックアドレスに限定し、ログインや外部公開は設けない。
- 起動方法とMCPの接続設定をREADMEに記載する。AIの接続自体は対応クライアント側で設定する。
- 実データはGit管理から外し、アプリを更新しても保存データを保持する。

## MVPに含めないもの

共有・権限管理、コメント、通知、外部サービス連携、全文検索、リアルタイム共同編集、派生資料の自動生成、組み込みAI、任意HTMLの取り込み、自由なレイアウト、画像のAI取得、複数形式の入出力。

## 実装時の検証

- 成功条件の一連の操作を、ブラウザとMCPの両方を使って確認する。
- 全部品を含む文書で、人間の編集、AIの取得と修正、再表示を行い、表・リンク・画像・コードの内容が失われないことを確認する。
- 未対応HTMLを送った場合、エラーとなり保存済み文書が変わらないことを確認する。
- 人間が編集中にAIが保存した場合、古い版での保存が拒否され、編集中の内容が保持されることを確認する。
- 直前の保存への取り消しと、再起動後の文書・画像の保持を確認する。
- 型チェック、関連テスト、lintを実行する。
